# Taste
- Writes very terse, informal, unpunctuated instructions that describe desired behavior rather than technical specs (e.g. "When we click on that location, then we have a map ... map active that location on map and location list also"); expects the agent to infer intent and ask a short clarifying question when the request is ambiguous. Confidence: 0.6
- Wants interactions to keep the user inside the app: clicking a result should drive the site's own in-page map/state and highlight the matching card rather than opening an external map link (e.g. "don't open the map use my map and my location pin pointed out that location"). Confidence: 0.55
- Asks for text/labels to be centered on the page when calling out a message ("Aligned ... in the center"). Confidence: 0.4
- When adding or tweaking a feature/effect (e.g. scroll animation), expects the existing visual design to be preserved exactly — colors, fonts, images, sizes, rotation and border-radius must not change ("Don't change my design color font images sizes, images rotation radius all the thing"; "don't change the image size keep the image size as it was"; "don't change UI and UX anything it's good"; "don't change the design at all"). Confidence: 0.9
- Prefers sections/blocks to have breathing room rather than filling the viewport flush to the edge — wants spacing above a pinned section so it doesn't sit at top zero, and reduced vertical padding over full-bleed ("don't fully take the second section ... keep some space there"). Confidence: 0.45
- Dislikes decorative filters on images — wants them shown fully/opaque rather than faded or blurred, and made larger when they feel small ("don't add opacity on image one show and also increase the size of image of both images"). Avoid introducing opacity/blur effects on images unless explicitly asked. Confidence: 0.4
- Wants related animations (e.g. text reveal and image slide-up) synchronized so they finish at the same time rather than ending at different moments. Confidence: 0.5
- Prefers scroll-progress-driven visual effects whose onset is tied to an element's position in the viewport — e.g. keep the first image sharp until the second image has risen to ~70–80% up the screen, then blur/dim it progressively (completing as the animation lands) rather than applying a static filter from the start. Confidence: 0.75
- Wants images enlarged when they feel small, and asks for "a bit more" size rather than accepting a minimal adjustment. Confidence: 0.55
- Prefers reusing an existing component/popup/animation for equivalent actions instead of building a new one (e.g. "show the same pop up as get a delivery" when wiring Click & Collect; "copy that animation and apply that animation" when asked to add an effect to another page; "I want the same effect ... as in why choose crispy" to reuse the ScrollTabs animation on the How To Get Started section). Confidence: 0.75
- Prefers a form's submit button be disabled (grayed out) until all required fields and checkboxes are complete, then enabled. Confidence: 0.6
- Prefers numbered/tabbed content presented as a pinned scroll section: the section stays fixed while a large number counts up and the matching point's text swaps in as you scroll, mirroring the homepage welcome animation. Confidence: 0.55
- Prefers numbered/stepped content laid out in a horizontal row (number → title + description → dot indicator) rather than a single vertical column, and asks to reuse the previous row design instead of a new stacked layout. Confidence: 0.6
- Prefers text to scale down responsively on smaller screens (viewport-based `clamp`/`vw` sizing) rather than staying at fixed sizes when making layouts responsive. Confidence: 0.55
- When only a specific content change is requested (e.g. update a heading/description's wording), wants ONLY that text changed — the existing layout/structure must stay exactly as the user designed it, and any earlier layout alteration should be reverted rather than kept ("don't change my layout ... just change the submit your inquiry text ... don't change the layout"). Confidence: 0.7
- When pasting a reference JSX/code snippet, expects the target section to be restyled to match that snippet's fonts, structure, spacing/gaps, and overall placement exactly, while preserving the existing animation/behavior ("use these phone style pending and structure keep the current animation but choose these font style structure gaping and overall plasing"; "use mine pill ... use this much gap in each pill and these are the colors"). Confidence: 0.6
- When the user asks for "the same effect as [another section]", they want only that specific behavior (e.g. pinning on scroll) applied to the existing section — keeping its original card, icon, and content — not the other section's whole component swapped in (which introduced unwanted numbers/step layout). Interpret "same effect" narrowly and preserve the target section's own design. Confidence: 0.7
- For a pinned-on-scroll step section, prefers the existing card/layout and icon to stay put while only the inner heading + subtext swap and the dot progress indicator advances as the user scrolls — rather than adding numbered steps or a large counter. Confidence: 0.6
